# 코인·코스튬 규칙과 기록 (1.4.0)

앱 안에서 쓰는 코인을 모아 고양이 캐릭터 코스튬을 사고 적용하는 기능. 규칙(§1)·영상 넣는 절차(§2)·화면(§3)의 기준 문서다. §4는 1.4.0을 여러 세션이 나눠 만들 때의 작업 분담 기록으로, 지금 작업에는 적용하지 않는다.
API 요청·응답은 [`API.md` "코인·코스튬"](API.md#코인코스튬), DB는 `backend/src/main/resources/db/migration/V8__coins_outfits.sql`과 그 뒤 V9~V11·V13 상품 변경.
규칙을 바꾸면 이 문서·API.md도 함께 갱신한다. 이미 운영에 적용한 마이그레이션은 수정하지 않고, main과 열린 PR의 번호를 확인해 다음 번호로 추가한다.

## 2. 영상 파일 넣기

캐릭터는 **16:9 MP4 영상을 소리 없이 반복 재생**한다(처음엔 WebP로 정했다가 바꿈: 용량이 작고 저가폰에서도 부드럽다). 기존 레벨 PNG 20장(`assets/characters/`)은 삭제했다.
**받은 영상은 그대로 넣지 않고 `frontend/scripts/prepare-outfit-video.py`로 변환해서 넣는다.** 받은 영상은 배경이 무대 색과 달라서(조명 그라데이션), 스크립트가 가장자리를 무대 색으로 녹인다.

### 받는 영상 / 변환 결과

| | 받는 영상(제작 쪽) | 저장소에 들어가는 파일(스크립트 결과) |
|---|---|---|
| 비율 | 16:9 가로형(예: 1280×720) | 1280×720 |
| 길이 | 2~4초, 첫 장면과 끝 장면이 이어지게 | 그대로 |
| 코덱·소리 | 상관없음(HEVC·소리 있어도 됨) | H.264, 소리 없음, 300KB 안팎 |
| 배경 | 밝은 단색 계열이면 됨 | 가장자리 120×96px을 `#EEF2FA`로 녹임(가장자리 색 = 무대 색) |
| 파일 | | `assets/outfits/<id>.mp4` + 첫 장면 `<id>.jpg` |

id: `costume-lv1` … `costume-lv6`, `outfit-01` … `outfit-10`. 현재 들어온 파일: **`costume-lv1`(광부)**, **`outfit-01`(잭팟)**, **`outfit-02`(직장냥이)**, **`outfit-03`(선비냥이)**, **`outfit-04`(유령냥이)**, **`outfit-05`(고양마녀)**, **`outfit-07`(달밤 낚시 고양이)**, **`outfit-08`(산타냥이, `cat-santa.mp4`·`cat-santa.png`)**, **`costume-lv2`(농부, `cat-farmer.mp4`, 11-08, 첫 장면은 영상에서 뽑음)**, **`costume-lv3`(상인, `cat-trader.mp4`)**, **`costume-lv4`(기사, `cat-knight.mp4`)**, **`costume-lv5`(귀족, `cat-noble.mp4`)**, **`costume-lv6`(왕족, `cat-king.mp4`)**(11-09, `--scale` 없이). 농부·상인은 캐릭터가 화면을 가득 채워 스크립트 `--scale`(농부 0.8, 상인 0.85)로 줄여 가운데에 두었다(기기에서 광부와 비슷한 크기로 보이게, 기사는 원래 크기). 처음 두 개의 첫 장면은 제작 쪽이 준 썸네일(`cat-000-thumbnail.jpg`)을 스크립트 세 번째 인자로 넣어 만들었다. 광부는 10-23 `cat-mine.mp4`로 다시 만들었다(첫 장면은 영상에서 뽑음).

### 추가·전환 기록

**레벨 코스튬 전환(2026-10-22, V10 · 운영 배포 완료):** 잭팟·직장냥이의 임시 판매를 끝내고 위 3단계로 전환했다. 기존 id와 영상 파일은 그대로 사용한다. 기존 구매자는 레벨과 관계없이 계속 보유·적용하며 구매 내역마다 낸 코인(각 200, 두 벌이면 400)을 `REFUND`로 한 번 돌려받는다. 다음 check-in에서 안내하고 닫을 때 ack한다. 이 시점에는 코인 상품이 하나도 켜져 있지 않았다(다음 날 V11로 두 개를 켰다).

**V10 반영 순서:** REFUND 안내를 포함한 1.4.0용 앱 원격 업데이트 → 수신 확인 → 서버 V10 적용. 이전 앱은 REFUND 안내를 알지 못하므로 앱을 먼저 반영한다. 새 네이티브 빌드·패키지 변경은 없다.

실제 반영: production 앱 그룹 `6d140975` 게시 후 사용자 지시로 10-22 17:02 KST 서버 V10 배포. 적용 로그와 운영 health UP은 확인했고, 앱 실기기 수신·반환 모달은 10-23 사용자가 확인했다([HANDOFF](HANDOFF.md) 0-레벨).

**선비냥이·유령냥이 추가(2026-10-23, V11):** `cat-seonbi.mp4`는 `outfit-03`, `cat-ghost.mp4`·`cat-ghost.png`는 `outfit-04`로 연결한다(`python scripts/prepare-outfit-video.py <영상> <id> [첫 화면 이미지]`, 보정 옵션 없음). 선비냥이가 상점 앞칸(정렬 순서 103)이고 유령냥이가 뒤(104)다. V11이 이름·가격(각 200코인)을 정하고 판매를 켠다. 레벨 코스튬 전환(V10) 뒤 첫 코인 구매 코스튬이다. 선비냥이 영상 오른쪽 아래(모자 챙 부근)에 Gemini 워터마크(✦)가 흐리게 남아 있다. 반영 순서는 **앱 원격 업데이트 수신 확인 → 서버 V11 적용**(먼저 켜면 옛 앱이 기본 캐릭터 그림으로 판다). 실제로는 앱 게시(10-23 그룹 `e270ca8b`) 뒤 수신 확인 전에 서버 V11을 배포했다(10-23 11:50 KST, HANDOFF 0-1.4.0-다음).

**직장냥이 추가(2026-10-21):** `cat_salary.mp4`·`cat_salary.jpg`를 `outfit-02`로 연결한다. V9가 이름을 직장냥이, 가격을 200코인으로 설정하고 판매를 켠다. 변환 명령은 `python scripts/prepare-outfit-video.py <cat_salary.mp4> outfit-02 <cat_salary.jpg> --clear-top-left`. 이 옵션은 1280×720 기준 좌상단 240×90px을 무대 색으로 덮고 바깥 40px 경계를 녹여 배경색 텍스트를 영상·정지 그림 모두에서 지운다. 다른 코스튬에는 기본 보정을 그대로 쓴다.

꾸미기 미리보기·목록·구매 완료 문구에는 이름을 표시하지 않는다(접근성 라벨에는 유지). 상점 목록의 그림 바로 아래는 안 산 상품이면 코인 그림과 가격(`🪙 200`), 산 코스튬이면 `보유 중`, 지금 적용 중이면 `적용 중`을 표시한다(11-04 바꿈, 그 전에는 보유·적용 여부와 관계없이 가격만 표시했다).

반영 순서는 **1.4.0용 앱 원격 업데이트 수신·직장냥이 영상 확인 → 서버 V9 적용**이다. 네이티브 의존성·버전 변경은 없다. 원격 업데이트를 받지 않은 기존 1.4.0은 새 상품을 기본 캐릭터로 표시하므로, 서버 활성화 전 앱 수신을 확인한다. (직장냥이는 다음 날 V10에서 Lv.2 레벨 코스튬으로 옮겼다.)

### 그리는 규칙

- 코스튬 그림은 **`src/service/OutfitView.tsx`의 `<OutfitView outfitId play />`로만** 그린다. `play`면 `expo-video`로 반복 재생하고(다른 화면으로 가면 멈춤, 동작 줄이기 설정이면 정지 그림), 영상이 준비되기 전에는 첫 장면을 덮어 둔다
- 칸은 **16:9**. 홈은 화면 폭을 꽉 채운다(`CharacterStage`의 `character` 칸, 최대 640). 가장자리가 무대 색이라 무대(`colors.stage`) 위에 올리면 경계가 보이지 않는다. 흰 카드 위에 올릴 때는 칸 배경을 `colors.stage`로 깐다
- **재생 중인 영상은 화면당 하나.** 홈 캐릭터, 꾸미기 위쪽 미리보기만 `play`. 꾸미기 목록 칸과 구매 완료 모달은 `play={false}`(정지 그림)
- 화면에서 `require`로 그림·영상 파일을 직접 부르지 않는다. 파일 연결은 `outfits.ts` 한 곳
- 영상이 아직 없는 코스튬은 기본 캐릭터(광부) 첫 장면을 보여 준다. 상점 그림 아래에는 가격만 표시하므로, 영상이 없는 상품은 운영에서 판매를 켜지 않는다
- 판매 여부는 마이그레이션이 정한다: V8이 잭팟, V9가 직장냥이를 켰고, V10이 두 벌을 레벨 코스튬으로 옮겼고, V11이 선비냥이·유령냥이를 켰다. 나머지 상점 상품은 꺼져 있다. 꺼진 상품도 이미 산 사람의 목록에는 나온다. 로컬·CI는 `app.outfits.show-inactive=true`(`application-local.yml`)로 꺼진 상품도 보이고 살 수 있어서 구매 흐름을 시험할 수 있다

### 영상을 받았을 때 (반영 절차)

1. `cd frontend && python scripts/prepare-outfit-video.py <받은 영상.mp4> <id>` (ffmpeg가 없으면 먼저 `pip install imageio-ffmpeg`)
2. 스크립트가 출력한 한 줄을 `outfits.ts`의 `VIDEOS`에 추가 → 화면 수정은 필요 없다
3. 상점 상품이면 백엔드에 `V{n}__outfits_<내용>.sql` 추가: `UPDATE outfits SET name = '<상품 이름>', active = TRUE WHERE id = 'outfit-0N';`
4. 배포 순서: **앱(원격 업데이트 또는 1.4.0 빌드) 먼저, 서버(마이그레이션) 나중**. 서버를 먼저 켜면 옛 앱에서 기본 캐릭터 그림으로 팔린다
5. 실기기(저가 Android 포함)에서 첫 화면 깜빡임·반복 이음새를 확인한다
