# PRD — 텅장관리 앱

> 개발 기준 요약이다. 기능별 화면·API·확인 방법과 근거는 [FEATURES.md](FEATURES.md), 계산 규칙은 [policies.md](policies.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 배포·출시 현황은 [HANDOFF.md](HANDOFF.md)에 있다. 이 문서를 바꾸는 PR에는 `spec-change` 라벨과 [CHANGELOG](CHANGELOG.md) 한 줄이 필요하다.

## 1. 서비스 목표

**"이번 수입일까지, 오늘 얼마 써도 되는지."**

사회초년생이 **직접 입력한** 잔액·수입일·고정지출·카드 미결제액·매달 저축할 돈과 기록된 거래로, 서버가 "오늘 쓸 수 있는 돈"을 계산해 보여 준다. 예산을 지킨 날만큼 캐릭터가 자라고, 수입일 전날 남은 돈을 시드머니로 옮겨 모은다. 모은 시드머니는 사용자가 원하면 데스크톱 웹사이트([flexable-web](https://github.com/shinds-team7/flexable-web))에서 투자·적금 연습에 쓴다.

화면 문구는 "입력한 잔액·기록 기준 추정"이다. 실제 은행 잔액과 다를 수 있다.

## 2. 사용자

월급으로 생활비를 꾸리는 사회초년생([README](../README.md)). 나이·소득대 같은 구체적인 정의는 웹과 같이 쓰며 [웹 PRD](https://github.com/shinds-team7/flexable-web/blob/main/docs/PRD.md) §2에 있다.

## 3. 핵심 기능과 현재 상태

상태는 2026-11-11 기준이다. 운영 서버는 11-10 배포본이고, 앱은 Play 스토어 2.0.1(11-11 출시, 최소 지원 버전 2.0.1)이다. 코드에 있는 것과 운영에 배포된 것은 다를 수 있다(배포·실기기 확인은 HANDOFF).

| 기능 | 무엇 | 상태 |
|---|---|---|
| 계정 | 이메일·카카오·Google 가입·로그인·로그아웃, 계정·데이터 즉시 삭제(앱·웹 공개 페이지) | 구현·배포 |
| 초기 예산 설정 | 5단계: 잔액(생활비 잔액·모아둔 돈) → 수입(수입일·수입액·카드 미결제액) → 고정지출 → 매달 저축할 돈 → 완료. 마이에서 저장된 설정 전체를 한 화면으로 다시 설정 | 구현·배포 |
| 오늘 쓸 수 있는 돈 | 캐릭터 홈: 캐릭터 영상·승급 게이지, 오늘 쓸 수 있는 돈 카드(넘기면 시드머니 카드), 이번 주 쓸 수 있는 돈, 다음 수입일까지 남은 생활비, 요일별 배분. 서버 계산([policies §2](policies.md#2-오늘-쓸-수-있는-돈get-budgettoday-budgetbudgetcalculator)) | 구현·배포 |
| 요일별 생활비 배분 | 하루 예산을 요일 비중대로 나눔. 프리셋(기본·내 기록 기준·주말 넉넉히·평일 넉넉히)과 요일 막대 끌어 직접 조정. 서버 계산([policies §5](policies.md#5-요일별-비중getput-budgetday-weights-budgetdayweights)) | 구현·배포 |

| 소비 분석 | 이번 달(기본)·이번 주·전체(3개월·6개월·1년) 기간별 카테고리·일별 합계, 도넛·막대 항목 정보, 카테고리별 거래 목록 | 구현·배포 |
| 예정 지출 | 미래 날짜에 별도 등록·수정·삭제. 실제 거래를 자동으로 만들지는 않지만, 수입일 전날까지의 예정 금액은 남은 생활비에서 먼저 빼고 그날 하루 예산에 더해 예산에 반영([policies §6](policies.md#6-예정-지출홈-평일-내역2026-10-30-사용자-요청)) | 구현·배포 |
| AI 메이트(챗봇) | Gemini가 서버 계산 예산과 카테고리별 지출 합계(입력한 잔액·기록 기준)로 소비 흐름을 설명하고 아끼는 방법을 추천. 말투 3가지(첫 진입 때 선택). 요일별 배분 변경은 제안만 하고 사용자가 확인하면 저장. 일정을 말하면(예: "금요일 저녁에 술약속") 서버가 입력한 거래 기록으로 쓸 금액을 예측해 "○일에 ○원 쓸 예정으로 등록할까요?"라고 묻고, 확인하면 예정 지출로 등록해 하루 예산에 반영. 실제 받은 수입 거래 등록·수정과 월 수입액·수입일 변경도 제안하고 [반영]하면 저장([policies §8](policies.md#8-ai-메이트)). 음성으로 질문 입력(녹음 저장 없음, 최종 결과 자동 전송) | 구현·배포. 메뉴의 "약속 설정"은 안내와 예시만 띄우고, 일정 등록은 대화로 한다 |
| 시드머니 | 모아둔 돈 + 수입일 전날 반영(매달 저축할 돈 / 남은 돈 전부 / 직접 입력) + 지금 예산에서 바로 보내기, 기기 알림 20시. 카드에는 지금까지 모은 돈·이번 달 모을 돈, 모은 기록과 총액 정정 | 구현·배포 |

| 알림 | 앱 안 알림함(최근 30일), 기록 알림(시간 선택, Android), Android 알림창에 오늘 남은 예산 상시 표시(기본 꺼짐, [기록]·[홈] 버튼). 모두 기기 안 알림이고 서버 푸시는 없다 | 구현·배포 |

## 4. 개발 범위

- 플랫폼: Android(Google Play 프로덕션, 2.0.1)와 웹(같은 Expo 코드).
- 온라인 전용. 모든 계산과 저장은 앱 서버(`backend/`)가 하고, 앱은 결과를 그린다.
- 웹사이트는 서버·DB·계정을 따로 쓴다. 앱 정보는 사용자가 [앱 연동하기]를 했을 때만 서버끼리 준다([ARCHITECTURE](ARCHITECTURE.md#앱과-웹사이트)).
- 다음 할 일과 출시 일정은 [HANDOFF](HANDOFF.md) "지금 상태"·"다음 할 일".

## 5. 하지 않는 것

시연(flexable-web `/m`)이나 기획 문서에 나와도 서비스에는 없다. 스토어 문구·앱 화면에 쓰지 않는다.

- 계좌 연결(오픈뱅킹)
- 지원 카드 앱(신한·삼성·현대·KB국민·롯데) 국내 원화 승인 이외의 결제 알림·문자 자동 기록, 서버 푸시 알림(기기 안의 시드머니·기록·상시 알림만 있음). 카드 취소·해외·불명확한 알림은 자동 반영하지 않는다
- 고액 지출 자동 계획, 정산(1/N)
- 비밀번호 찾기, 이메일 인증
- 오프라인 수동 거래 저장(SQLite·outbox). 카드 자동 기록의 기기 알림 대기열은 서버 기록 전 임시 수집에 한정한다
- 코인을 현금·다른 재화로 바꾸거나 다른 회원에게 넘기기(약관 제2조 4)

근거는 [FEATURES "미구현"](FEATURES.md#미구현-서비스에-없음), [이용약관](play-store/terms.md).
