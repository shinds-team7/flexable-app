# PRD — 텅장관리 앱

> 개발 기준 요약이다. 기능별 화면·API·확인 방법과 근거는 [FEATURES.md](FEATURES.md), 계산 규칙은 [policies.md](policies.md), 구조는 [ARCHITECTURE.md](ARCHITECTURE.md), 배포·출시 현황은 [HANDOFF.md](HANDOFF.md)에 있다. 이 문서를 바꾸는 PR에는 `spec-change` 라벨과 [CHANGELOG](CHANGELOG.md) 한 줄이 필요하다.

## 1. 서비스 목표

**"이번 수입일까지, 오늘 얼마 써도 되는지."**

사회초년생이 **직접 입력한** 잔액·수입일·고정지출·카드 미결제액·매달 저축할 돈과 기록된 거래로, 서버가 "오늘 쓸 수 있는 돈"을 계산해 보여 준다. 예산을 지킨 날만큼 캐릭터가 자라고, 수입일 전날 남은 돈을 시드머니로 옮겨 모은다. 모은 시드머니는 사용자가 원하면 데스크톱 웹사이트([flexable-web](https://github.com/shinds-team7/flexable-web))에서 투자·적금 연습에 쓴다.

화면 문구는 "입력한 잔액·기록 기준 추정"이다. 실제 은행 잔액과 다를 수 있다.

## 2. 사용자

월급으로 생활비를 꾸리는 사회초년생([README](../README.md)). 나이·소득대 같은 구체적인 정의는 웹과 같이 쓰며 [웹 PRD](https://github.com/shinds-team7/flexable-web/blob/main/docs/PRD.md) §2에 있다.

## 4. 개발 범위

- 플랫폼: Android(Google Play 비공개 테스트 중)와 웹(같은 Expo 코드).
- 온라인 전용. 모든 계산과 저장은 앱 서버(`backend/`)가 하고, 앱은 결과를 그린다.
- 웹사이트는 서버·DB·계정을 따로 쓴다. 앱 정보는 사용자가 [앱 연동하기]를 했을 때만 서버끼리 준다([ARCHITECTURE](ARCHITECTURE.md#앱과-웹사이트)).
- 다음 할 일과 출시 일정은 [HANDOFF](HANDOFF.md) "지금 상태와 남은 일".

## 5. 하지 않는 것

시연(flexable-web `/m`)이나 기획 문서에 나와도 서비스에는 없다. 스토어 문구·앱 화면에 쓰지 않는다.

- 계좌 연결(오픈뱅킹), AI 소비 분석·추천
- 신한 SOL페이 국내 원화 승인 이외의 결제 알림·문자 자동 기록, 서버 푸시 알림(시드머니·기록 알림은 기기 안에서 예약). 신한카드 취소·해외·불명확한 알림은 자동 반영하지 않는다
- 예정 지출(상태·취소)·고액 지출 계획, 정산(1/N)
- 비밀번호 찾기, 이메일 인증
- 오프라인 수동 거래 저장(SQLite·outbox). 신한카드 자동 기록의 기기 알림 대기열은 서버 기록 전 임시 수집에 한정한다
- 코인을 현금·다른 재화로 바꾸거나 다른 회원에게 넘기기(약관 제2조 4)

근거는 [FEATURES "미구현"](FEATURES.md#미구현-서비스에-없음), [이용약관](play-store/terms.md).
