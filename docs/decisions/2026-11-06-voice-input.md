# AI 메이트 음성 입력과 개인정보처리방침 추가 개정(2)

- 날짜: 2026-11-06 · 결정한 사람: SXXNHU(채팅에서 선택, Issue #256 4번) · 상태: **승인, 구현**
- 영향: 앱 화면(AI 메이트 입력창 마이크 버튼), Android 네이티브(`expo-speech-recognition`, `RECORD_AUDIO` 권한 → **새 빌드 필요**), 개인정보처리방침(정본 `docs/play-store/privacy-policy.md`와 앱·웹 `/privacy`). 앱 서버·API 계약은 바뀌지 않는다
- 바뀌는 기준 문서: `play-store/privacy-policy.md`, `play-store/README.md` §3.6·§3.8, `FEATURES.md`

## 결정

1. **인식 방식 = 기기·브라우저 음성 인식.** Android 앱은 시스템 음성 인식 서비스(보통 Google 앱), 웹은 브라우저 Web Speech API(Chrome 등)를 쓴다(`expo-speech-recognition` 57.x). 우리 서버나 별도 음성 API로 음성을 보내지 않는다. 기기 안 인식(on-device)만 쓰도록 강제하지 않는다. 한국어 오프라인 모델이 없는 기기가 많아서다.
2. **결과 처리 = 입력창에만 넣는다.** 말하는 동안의 중간 결과와 최종 결과를 입력창에 쓰고(입력창에 글이 있으면 그 뒤에 붙임), 보내기는 사용자가 [보내기]를 눌러야 한다. 자동 전송하지 않는다.
3. **녹음 파일을 만들지 않는다**(`recordingOptions` 안 씀). 음성 답변 재생은 범위 밖이다.
4. **지원 범위**: 음성 인식을 쓸 수 있는 Android 새 빌드와 브라우저(`isRecognitionAvailable()`)에서만 마이크 버튼이 보인다. 네이티브 모듈이 없는 옛 빌드는 JS가 모듈을 늦게 불러와(`requireOptionalNativeModule` 확인 뒤 `require`) 버튼만 숨긴다. 그래서 원격 업데이트로 이 JS가 옛 빌드에 가도 앱이 죽지 않는다.
5. **권한**: 마이크 버튼을 처음 누를 때 묻는다. 거부하거나 인식에 실패하면 입력창 위에 안내를 띄우고 글자 입력은 그대로 쓴다. 예전에 `expo-image-picker`의 `microphonePermission: false`가 `RECORD_AUDIO`를 매니페스트에서 지우고 있어서 그 설정을 뺐다(카메라 차단은 유지).
6. **개인정보처리방침 추가 개정(2)**: 음성 입력과 함께, 그동안 빠져 있던 AI 메이트(Google Gemini)로 보내는 메시지·예산 요약, Google 처리 위탁, 국외 이전을 적었다. 정식 출시 전이라 공고일에 바로 시행한다(11-04 광고 개정과 같은 방식). 음성 입력은 이 기능이 들어간 앱 버전을 쓰는 이용자부터 적용한다.

## 확인이 남은 것(사람)

- Gemini API를 무료 등급으로 쓰는지 유료 등급으로 쓰는지에 따라 Google의 데이터 이용 조건이 다르다. 방침에는 "Google의 Gemini API 정책에 따름"으로만 적었다. 등급을 확인하고 필요하면 문구를 보강한다.
- Play 데이터 보안 양식: AI 메이트 메시지(기타 사용자 제작 콘텐츠, 일시적 처리)를 추가한다. 음성(오디오)은 앱이 수집하지 않는 것으로 신고하는 쪽을 권하며, 사람이 Play 안내를 다시 확인해 정한다(`play-store/README.md` §3.6).
- 새 빌드 전 앱 버전을 올릴지(광고 SDK 때 #245처럼 런타임 분리)는 사람이 정한다.
