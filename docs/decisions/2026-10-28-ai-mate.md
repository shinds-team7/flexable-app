# AI 메이트(챗봇): Gemini로 소비 흐름 설명·추천, 배분 변경은 확인 뒤 저장

- 날짜: 2026-10-28 · 결정한 사람: SXXNHU(채팅에서 선택) · 관련: PR(이 PR)
- 영향: 앱 서버(새 API `POST /chat/messages`, 외부 호출 Gemini) / 앱 화면(챗봇 화면 연결은 다음 PR). 웹은 영향 없음

## 결정

1. PRD §5 "하지 않는 것"에서 **AI 소비 분석·추천을 뺀다.** 앱 안 AI 메이트가 입력한 잔액·기록 기준으로 소비 흐름을 설명하고 아끼는 방법을 추천한다. 계좌 연결은 계속 하지 않는다.
2. 모델은 Google Gemini(REST `generateContent`)를 앱 서버에서 부른다. 키는 서버 `.env`의 `GEMINI_API_KEY`에만 두고, 없으면 503 `CHAT_UNAVAILABLE`로 답한다.
3. 모델에 보내는 사용자 정보는 **서버가 계산한 예산 요약과 카테고리별 지출 합계**까지다. 거래 제목·메모·개별 거래는 보내지 않는다.
4. 챗봇은 요일별 배분 프리셋 변경을 **제안만** 한다(`action`). 사용자가 확인 버튼을 누르면 앱이 기존 `PUT /budget/day-weights`로 저장한다. 거래·고정지출·잔액은 챗봇이 바꾸지 않는다.
5. 대화는 서버에 저장하지 않는다. 사용자별 1시간 30번으로 제한한다.

## 이유

- 1·3·4는 사용자가 채팅에서 골랐다(분석·추천 모두 범위에 넣음, 예산 요약 포함, 변경 전 확인).
- 예산 금액은 서버(`BudgetCalculator`)가 최종값이라는 공통 규칙을 지키려고 모델에는 계산값을 그대로 주고 다시 계산하지 말라고 지시한다. 저장도 모델이 아니라 기존 API가 한다.
- 대화를 저장하지 않으면 새 테이블·보관 기간·삭제 절차가 필요 없다. 앱 화면이 대화를 들고 있다.
- 호출 제한은 모델 비용과 키 남용을 막는다. 단일 서버라 메모리로 충분하다.

## 남은 일

- 사용자 기록 요약이 Google(국외)로 가므로 **운영에서 키를 넣기 전에** 개인정보처리방침·Play 데이터 보안 양식에 반영한다(사용자: 11월 개정 때 한꺼번에). 그 전에는 운영 `.env`에 키를 넣지 않는다.
- `AGENTS.md`의 "소비 패턴 분석처럼 없는 기능을 암시하는 말" 규칙은 그대로 둔다. AI 메이트 밖의 화면 문구에는 계속 적용한다.
