## 1. URL 표

시연은 전부 `/demo/...`. 기존 `/demo` 메뉴는 충돌하므로 `/demo/simulations`로 이동.

| 현재 | 변경 후 | 현재 | 변경 후 |
|---|---|---|---|
| `/` | `/demo` | `/schedule/new` | `/demo/schedule/new` |
| `/home2` | `/demo/home2` | `/tx/[id]` | `/demo/tx/[id]` |
| `/plan` | `/demo/plan` | `/settle/[id]` | `/demo/settle/[id]` |
| `/analysis` | `/demo/analysis` | `/onboarding[/account\|income\|fixed\|protect\|analyze]` | `/demo/onboarding/...` |
| `/transactions` | `/demo/transactions` | `/demo` (시뮬 메뉴) | `/demo/simulations` |
| `/my` | `/demo/my` | `/demo/pay?...` | `/demo/simulations/pay?...` |
| `/budget-detail`, `/notifications`, `/memory`, `/schedule` | `/demo/<같은 이름>` | `/demo/push?...` | `/demo/simulations/push?...` |

서비스·공개 경로(신규): `/` (서비스 홈/로그인 분기), `/auth/login`, `/auth/signup`, `/auth/recover`, `/onboarding/*`, `/transactions`, `/transactions/new`, `/inbox`, `/settings/auto-record`, `/my`, `/account/delete`, `/privacy`, `/delete-account`.

주의
- 앱 라우터에서는 구 `/analysis` 등을 시연으로 redirect하지 않는다(서비스가 같은 주소를 쓴다). 대신 이미 공유된 배포 링크(예: `/onboarding`)를 살리기 위해 `vercel.json`에 **임시(307) redirect**로 `/demo/...`에 연결한다. 서비스가 해당 경로를 쓰기 시작하는 C단계에서 그 경로의 redirect를 지운다. 브라우저가 기억하는 영구(308) redirect는 쓰지 않는다. `/`는 redirect하지 않는다. 서비스 미구현 단계에서는 `/`에 "준비 중" 페이지를 표시하고 시연을 몰래 대신 보여주지 않는다.
- 구 `/demo/pay`, `/demo/push`만 `/demo/simulations/...`로 redirect(쿼리 유지).
- 현재 `vercel.json`은 `/(.*) → /index.html` 전체 rewrite다. `/demo/...`, `/privacy`, `/delete-account` 직접 접근·새로고침이 동작하는지는 B단계에서 검증 예정(미검증).
- Expo Router `(demo)` 그룹은 URL에 안 붙는다. 실제 `demo/` 폴더 segment 사용.

## 2. 라우트·Provider 분리

```text
src/app/
  _layout.tsx            # SafeArea·Toast·폰 프레임만. AppStoreProvider 제거
  demo/_layout.tsx       # AppStoreProvider(시연), 시연 배너, 시연 전용 guard
  demo/(tabs)/...        # 현재 (tabs) 이동
  demo/onboarding/, demo/simulations/, demo/tx/, demo/settle/, ...
  (service)/_layout.tsx  # 서비스 인증 guard + ServiceStore (빈 원장으로 시작)
  privacy.tsx, delete-account.tsx   # guard 없음
src/demo/routes.ts       # demoHref('tx', id) 같은 helper — 문자열 치환 금지
```

- 현재 `(tabs)/_layout.tsx`의 `<Redirect href="/onboarding">`와 `AppHeader`·`HomeContent`·`SubHeader`·`ScheduleRow`·`AnalysisTabs`·`onboarding/*`·`demo/*`·`notifications.tsx`·`my.tsx`의 href(약 80곳)를 모두 helper 경유로 바꾼다. 전수 목록은 `grep -rnE "href|router\.|pathname|Redirect|'/"`로 만든다.
- 탭 활성 표시는 pathname 비교이므로 `/demo` prefix를 반영해야 한다(홈은 `/demo`, `/demo/home2`).
- localStorage 키 `flexable:demo:*`. 기존 키(온보딩 완료·홈 스타일)는 demo 쪽에서만 1회 이행.
- 공통 `components/`는 store·경로를 직접 import하지 않도록 props화. 경로·store에 결합된 `AppHeader`/`HomeContent`는 demo wrapper와 service wrapper로 분리.
- 프로덕션 Android 빌드에서 `demo/` 제외: Expo Router는 빌드 시 라우트 파일을 제외하는 공식 수단이 제한적이므로, (a) 환경변수 기반 `demo/_layout`에서 `<Redirect>` + 번들 미포함 검토, (b) 별도 app variant 중 택일은 G단계 전에 SDK 57 문서로 확인한다. 메뉴 숨김만으로는 불충분. B단계에서는 경로·provider 격리까지만 한다.

## 9. 서비스 홈 기준

서비스 홈(`/`)은 home2(캐릭터) 대신 **기존 시연 home(`/demo`) 레이아웃**을 기준으로 한다. 화면 구성은 재사용하되 데이터는 분리한다.

```text
┌──────────────────────────────┐
│ 텅장관리 flex-able        🔔 │  ← 서비스 헤더(시연 띠 없음)
│ 홈  거래  내역  마이          │
├──────────────────────────────┤
│ ┌── 오늘 쓸 수 있는 돈 ─────┐ │  TodayHeroCard 레이아웃 재사용
│ │ 32,400원                  │ │
│ │ 입력한 잔액·기록 기준 추정 │ │  ← 시연의 "05:00 계산" 문구 대신
│ │ ▮▮▮▮▮▯▯▯▯ 다음 수입일까지 │ │
│ │ 마지막 확인 10:12 · 근거 > │ │
│ └───────────────────────────┘ │
│ [확인 전 금액 25,000원 · 3건 >] │  ← 확인 대기함(C단계 이후)
│ ┌ 이번 주 쓸 수 있는 돈 ─────┐ │  panel 재사용
│ │ 다음 수입일까지 남은 생활비 │ │
│ └───────────────────────────┘ │
│ 요일별 하루 예산 (기본 배분)   │  "소비 패턴 분석" 배지 대신 "기본 배분"
│ [+ 거래 직접 기록]             │
└──────────────────────────────┘
```

- 재사용: `TodayHeroCard`, 이번 주 panel, `DowBudgetCard`의 **표시 부분**만. 각각 `useStore()` 대신 props(`summary`, `today`, `onPress...`)를 받는 presentational 컴포넌트로 분리한다.
- 시연 wrapper(`src/demo/...`)가 `AppStore` 값을 넘기고, 서비스 wrapper는 `ServiceStore` 값을 넘긴다. 서비스 쪽에서 `@/data/mock`, `@/store/AppStore`, `@/ai/*`를 import하지 않는다(lint 규칙 또는 grep 검사로 확인).
- 서비스 홈에서 빼는 것: 이번 주 후보 거래(AI 일정), 고액 지출 계획, 지난 일정 정산 요청, 캐릭터·등급 뱃지. 1.0.0 범위에 없는 기능이다.
- 빈 원장: 히어로 대신 "초기 예산을 설정하면 오늘 쓸 수 있는 돈을 계산해요" + `[예산 설정하기]`. 거래가 없으면 "아직 기록한 거래가 없어요" + `[거래 직접 기록]`.
- 요일별 예산: 서비스에서는 시연 가중치를 "기본 배분"으로만 표시하고 "소비 패턴 분석" 문구를 쓰지 않는다.

### 10.2 가입 `/auth/signup`

```text
┌ ← 회원가입 ───────────────────┐
│ 이메일    [               ]   │
│ 비밀번호  [               ] 👁 │
│   8자 이상, 영문·숫자 포함     │
│ 비밀번호 확인 [           ]    │
│ ☐ (필수) 서비스 이용약관 보기> │
│ ☐ (필수) 개인정보 수집·이용 보기>│
│ [ 가입하기 ]  (조건 충족 전 비활성) │
└──────────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 입력 중 | 필드 아래 규칙 안내(색 + 텍스트), 제출 전 오류 표시 안 함 |
| 형식 오류 | 해당 필드 아래 `이메일 형식을 확인해 주세요` 등. 첫 오류 필드로 포커스 |
| 제출 중 | 버튼 로딩, 중복 클릭 차단 |
| 이미 가입된 이메일 | `이 이메일로 가입할 수 없어요. 로그인하거나 비밀번호를 찾아보세요` (계정 존재 여부를 직접 노출하지 않는 문구) |
| 네트워크 오류 | `연결이 불안정해요. 입력한 내용은 그대로 있어요` + 다시 시도 |
| 성공 | 서버 응답 후에만 `/onboarding`으로 이동 |
| 이메일 인증 | 업체 미정. 미구현 상태에서는 인증 단계 자체를 노출하지 않는다(가짜 성공 화면 금지) |

체크박스는 기본 해제. 약관·처리방침 링크는 공개 `/privacy`(약관 페이지는 운영 정보 확정 후).

### 10.3 로그인 `/auth/login`

```text
┌ ← 로그인 ────────────────────┐
│ 이메일    [               ]   │
│ 비밀번호  [               ] 👁 │
│ [ 로그인 ]                     │
│ 비밀번호를 잊었어요 · 회원가입 │
└──────────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 자격 증명 오류 | `이메일 또는 비밀번호가 맞지 않아요` (어느 쪽인지 구분하지 않음). 비밀번호 필드만 비움 |
| 시도 제한 | `잠시 후 다시 시도해 주세요` + 남은 시간(서버가 주는 경우) |
| 네트워크 오류 | `연결이 불안정해요` + 다시 시도 |
| 성공 | 초기 예산 미설정 → `/onboarding`, 설정 완료 → `/` |
| 탈퇴한 계정/세션 만료 | 로그인 화면으로 이동 + `다시 로그인해 주세요` 토스트, 로컬 데이터 정리 |

### 10.4 비밀번호 찾기 `/auth/recover`

- 이메일 입력 → `[재설정 메일 보내기]` → 입력과 무관하게 `입력한 이메일로 가입된 계정이 있으면 재설정 안내를 보냈어요`.
- 메일 업체 미정 단계에서는 이 화면 대신 `비밀번호 재설정은 준비 중이에요. 문의: (운영 정보 확정 후 표시)`를 보여준다. 성공한 척하지 않는다.

### 10.5 초기 예산 설정 `/onboarding/*` (서비스)

시연 온보딩의 `OnboardingFrame`(진행 바·하단 버튼) 레이아웃을 재사용한다. 계좌 연결·분석 단계는 없다.

| 단계 | 경로 | 입력 | 비고 |
|---|---|---|---|
| 1 | `/onboarding` | 소개: "입력한 정보로 오늘 쓸 수 있는 돈을 계산해요. 실제 은행 잔액과 다를 수 있어요" | `[시작하기]` |
| 2 | `/onboarding/balance` | 현재 잔액(원), 기준 시각(기본: 지금) | 기준 시각 이전 거래는 잔액에 이미 반영된 것으로 본다 |
| 3 | `/onboarding/income` | 수입일(1~31, 말일 옵션), 예정 수입액 | 시연 income 화면 재사용 |
| 4 | `/onboarding/fixed` | 고정지출 목록(이름·금액·날짜) | 0건 허용, 시연 fixed 재사용(Mock 기본값 없음) |
| 5 | `/onboarding/card` | 이미 사용한 카드 미결제액(선택) | 0원 기본 |
| 6 | `/onboarding/protect` | 보호 금액(선택) | 시연 protect 재사용 |
| 7 | `/onboarding/done` | 계산 결과 미리보기 + `[홈으로]` / `[자동 기록 설정하기]`(선택) | 자동 기록은 건너뛸 수 있음 |

```text
┌──────────────────────────────┐
│ ▮▮▮▯▯▯▯              2 / 7   │
│ 지금 통장에 얼마 있나요?      │
│ 입력한 금액부터 계산을 시작해요│
│                              │
│ [        1,250,000 원 ]      │
│ 기준: 오늘 10:12  변경 >     │
│                              │
│ 은행 앱에서 확인한 금액을     │
│ 그대로 입력하면 돼요          │
│ [ 다음 ]                      │
└──────────────────────────────┘
```

| 상태 | 표시 |
|---|---|
| 빈 값/0 | 잔액 0원은 허용(경고만: `잔액이 0원이면 오늘 쓸 수 있는 돈도 0원이에요`) |
| 형식 | 숫자만, 원 단위 정수, 천 단위 구분 표시, 최대 1조 미만 |
| 수입일 31일 | `매달 말일`로 안내(월말·윤년 처리) |
| 중간 이탈 | 입력값은 기기에 임시 보관, 다시 열면 이어서 진행 |
| 저장 실패 | 마지막 단계 `[완료]`에서 오류 시 입력 유지 + 다시 시도. 완료 화면은 저장 성공 후에만 |
| 결과 음수 | 미리보기에 `다음 수입일까지 N원이 부족해요` (danger) — 진행은 막지 않음 |

금지 문구: "계좌 연결", "최근 6개월 거래를 불러왔어요", "소비 패턴 분석".

### 10.6 공통 접근성·레이아웃

360px 폭에서 금액 입력 한 줄 유지, 키보드가 하단 버튼을 가리지 않게 스크롤, 글꼴 확대 200%에서 버튼 줄바꿈 허용, 모든 입력에 `accessibilityLabel`, 오류는 색 + 아이콘 + 텍스트.
